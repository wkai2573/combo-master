# 雲端戰績：全站共用的戰績資料庫

## 問題陳述

戰績只存在各自瀏覽器的本機儲存，換裝置就沒有，也無法看到所有玩家加總的角色勝率與回合數分布，無法用來評估卡片與角色的平衡。

## 解決方案

建立一個放在雲端的戰績資料庫，所有玩家正常結束的對局都上傳，戰績頁的統計來自全站資料。連線對局只由房主上傳，一場只留一筆。不需要登入，每個瀏覽器有匿名裝置代號用於限流。伺服器使用 Cloudflare Workers 加 D1，不需要信用卡。

## 使用者故事

1. 身為玩家，我想要打完的對局自動上傳到雲端，以便不必手動操作
2. 身為玩家，我想要打電腦的對局也上傳，以便樣本更多，並且仍可用對手類型篩選
3. 身為玩家，我想要連線對局只由房主上傳，以便一場不會被算兩次
4. 身為玩家，我想要離線判負、中途離開、有人開過作弊的對局不上傳，以便資料可信
5. 身為玩家，我想要戰績頁顯示全站所有玩家的統計，以便看到整體的角色強弱
6. 身為玩家，我想要版本複選決定從伺服器取哪些版本的資料，以便比較不同版本
7. 身為玩家，我想要沒有網路時對局照常進行，上傳失敗的紀錄存在本機，下次開啟時補傳，以便不遺失
8. 身為玩家，我想要補傳不會造成重複，以便重試是安全的
9. 身為玩家，我想要連不上伺服器時戰績頁顯示錯誤與重試按鈕，並顯示上次成功取得的資料，以便還能看資料
10. 身為玩家，我想要不用登入也不被蒐集個人資料，以便使用門檻低
11. 身為玩家，我想要我本機的舊紀錄保留在本機，不被上傳，以便全站統計不被沒有去重資訊的舊資料污染
12. 身為站長，我想要伺服器檢查欄位格式（版本、角色、結果、回合數）並限制單一裝置代號的寫入頻率，以便資料不被亂灌
13. 身為站長，我想要沒有任何刪除或修改的對外介面，以便別人不能清掉資料
14. 身為站長，我想要網站只接受來自本站與本機開發網址的請求，以便降低濫用
15. 身為站長，我想要伺服器的程式與資料表結構放在倉庫裡並有測試，以便日後維護
16. 身為玩家，我想要戰績頁移除「清除全部紀錄」按鈕，以便不會誤以為能刪全站資料

## 實作決策

- 戰績多兩個欄位：每場隨機產生的對局代號（供去重與補傳的冪等）與匿名裝置代號（限流）。原有欄位不變：版本、對手類型、我的角色、對手角色、結果、回合數、我是不是開局先攻。
- 伺服器對外只有兩個介面：新增一筆戰績（驗證、限流、同對局代號只收一次）、依版本集合與對手類型取得戰績清單（分頁，上限）。沒有刪除與修改。允許的來源只有本站網址與本機開發網址。
- 驗證：版本符合語意化版本格式；角色在已知角色名單內；結果為勝、負、平；回合數為合理範圍的整數；對局代號與裝置代號長度與字元限制；欄位一個都不能缺。限流以裝置代號為單位。
- 伺服器邏輯寫成一個「處理請求」的函式，輸入請求與資料庫介面，輸出回應；部署用的入口只負責接上 Cloudflare 的資料庫與路由，邏輯可以用假的資料庫在測試裡驅動。
- 資料表只存戰績欄位，對局代號有唯一限制。
- 前端新增「戰績倉庫」介面：上傳、取得、補傳佇列；實作一份連雲端的版本、一份記憶體假版本（測試用）。上傳失敗進入本機佇列，下次啟動與每次對局結束後重試，成功就移除。
- 場次層：由房主與單機場次在狀態轉為結束時產生戰績並交給戰績倉庫；訪客不上傳。轉換函式與不記規則（離線、中途離開、作弊）沿用。
- 戰績頁改為從戰績倉庫取得資料（依選的版本與對手類型），其餘統計沿用；載入中、錯誤、空狀態三種畫面；移除清除全部紀錄按鈕。舊的本機戰績儲存留著但不再讀取、不上傳（可在日後清理）。
- 部署：由本機的指令部署伺服器，部署前再向使用者確認；前端以建置時的設定得知伺服器網址，未設定時戰績功能優雅降級為「雲端戰績目前不可用」，對局不受影響。使用者只需要註冊免費帳號並授權一次，授權與其餘步驟由我帶著做；若過程出現信用卡要求就停止並改選方案。
- 文件：新增 ADR 說明為何選全站戰績、房主上傳、匿名裝置代號與 Cloudflare；README 補上伺服器的開發、測試與部署說明；詞彙表的戰績已更新。
- 版本：minor 升版為 0.37.0，更新日誌寫「戰績改為全站雲端統計」。

## 測試決策

好的測試只驗證外部行為：給定請求看回應與資料庫內容；給定對局結局看有沒有上傳與上傳內容。

- 伺服器處理函式（最高接縫）：用假資料庫驅動。合法請求寫入；欄位缺漏、版本格式錯誤、未知角色、非法結果、回合數越界一律拒絕；同對局代號重送只存一筆且回應成功；超過限流被拒絕；取得清單依版本與對手類型篩選並分頁；不接受的方法與來源被拒絕；沒有刪除路徑。
- 場次層：單機與房主對局結束上傳一筆，欄位正確；訪客不上傳；離線判負、中途離開、作弊不上傳；上傳失敗時對局不受影響且進入補傳佇列，下次重試成功後移除。
- 補傳佇列：容錯的讀寫、重試不重複。
- 戰績頁用到的統計函式沿用既有純函式測試。
- 不測介面元件本身，也不測 Cloudflare 的實際連線；實際部署以手動驗證一次寫入與取得。
- 先例：場次層與房主協定測試、戰績統計純函式測試、記憶體假傳輸的做法。

## 不在範圍內

- 登入、個人戰績、排行榜、跨裝置的個人合併。
- 本機舊紀錄的遷移上傳。
- 戰績的逐場明細、回放、牌組內容。
- 防作假的強驗證（簽章、登入）；目前只做格式驗證與限流。
- 資料刪除的介面；要刪資料由站長在伺服器端處理。
- 在伺服器端計算統計；統計仍在瀏覽器端用既有函式計算。
