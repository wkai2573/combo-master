# 03：停在影格與完整腳本，打到勝利

**要建置什麼：** 教學腳本支援「停在影格」步驟：教學場次只把影格送到符合條件的那一格為止，剩下的扣著，場次狀態的桌面是那一格的桌面（動畫速度關閉時畫面也停在那裡），玩家點擊後才送出後面的影格。說明文字可以帶入對局的實際數值（雙方總攻擊、總防禦、受到的傷害、範圍兩端）。補完腳本剩下的段落：對手收招 → 玩家出第二張梅花7 → 自動收招與重複連擊值說明 → 追擊步驟 → 對手翻出追擊判定卡 → 追擊失敗 → 追擊卡加入對手手中 → 玩家翻判定卡 → 追擊成功 → 追擊卡進追擊卡疊、攻擊力算進總攻擊 → 傷害計算（帶入實際數字）→ 勝負影格「牌組就是生命……恭喜你勝利了！」。所有文字套用規格的修正。這張完成後，教學能從頭走到玩家獲勝。

這張的整場測試就是 ADR 0008 的把關：卡表改了白板卡數值讓教學打不贏或某一步不合法時，它要失敗。

## Answer

已於 v0.49.2 生效。

- 腳本多了 `at-frame` 步驟，在 `src/tutorial/script.ts`：場次把引擎已經跑到、但還沒交給畫面的影格扣著，只送到符合的那一格，場次狀態裡的桌面就是那一格的桌面，點完才送後面的。接在停點後面的說明維持停住的那一格。
- 播放器多了批次的 `hold`：標了停住的批次，最後一格播完不收掉，連同它的特效一直停到下一批到來，特效包含收招文字、中央放大與傷害算式；這是為了讓「停在收招文字上」「高亮追擊失敗文字」成立，不然停下來時特效已經消失。動畫關閉時沒有特效，停點只剩桌面，依賴特效的高亮（收招、追擊成功與失敗文字、判定卡）不會出現。
- 說明文字的函式拿到顯示中的桌面與停住的那一格，數字（範圍兩端、連擊值、總攻擊、總防禦、傷害）都來自實際對局。傷害那一步依規格第 52 條寫「對手」，不是規格範例裡的「對方」。
- 說明框位置的純函式在 `src/ui/tutorialPlacement.ts`，也在這張做了，因為停在翻牌與追擊結果時，中央放大的牌正好在畫面中央，說明框不移開就看不到；票券 05 剩下手機版的逐項驗證。
- 勝負那一步點完之前，不顯示原本的對局結果視窗；點完之後暫時還是原本的視窗，票券 04 換成教學結束畫面。
- 整場測試（`tests/tutorialPursuit.test.ts`）就是 ADR 0008 的把關。
- 電腦版與手機版都用瀏覽器走過整段，標準速度與關閉動畫各一次。
