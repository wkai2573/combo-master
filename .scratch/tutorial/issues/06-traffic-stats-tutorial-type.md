# 06：流量統計的「教學」類型

**要建置什麼：** 流量統計的對戰類型新增「教學」。教學場次的開始與完成記成這個類型，不記成單機；伺服器的事件驗證接受它，仍然拒絕不認得的值；站長的流量統計報表把教學另外列出，不併進單機。戰績驗證不變。伺服器要重新部署才會收這個類型，部署前送出的教學事件會被拒絕，這可以接受；部署是對外動作，由使用者決定何時執行，票券只負責程式與測試。

**Blocked by（被誰阻擋）：** 01

**Status：** resolved

- [x] 教學場次開始與正常完成時，流量統計收到的對戰類型是「教學」；中途離開不記完成（測試，比照場次統計的測試）
- [x] 伺服器事件驗證接受「教學」、拒絕不認得的值（測試，比照既有伺服器測試）

## Answer

已於 v0.49.4 生效，但伺服器與資料庫還沒更新，要站長自己執行下面兩步才會真的收到教學事件。

- 前端：流量統計的對戰類型 `PlayType` 多了 `tutorial`；教學場次開始、走到結束畫面時送事件，中途離開只有開始。戰績的對手類型仍只有電腦與玩家，教學不送戰績。
- 伺服器：事件驗證接受 `tutorial`，仍拒絕不認得的值；戰績驗證不變，送 `tutorial` 會被拒絕。
- 報表：「依對戰類型」多一列「教學」；總覽與每日、依版本的玩過、玩完與場次不算教學，免得教學把單機的漏斗墊高。
- 規格沒提到、但一定要處理：已上線的 `events` 資料表在 `opponent` 欄位有限制，只允許電腦與玩家，光部署伺服器，教學事件會被資料庫擋下。所以多了遷移檔 `server/migrations/0001-events-allow-tutorial.sql`，重建資料表並搬資料，可重複執行，測試在 `tests/eventsMigration.test.ts`；`schema.sql` 已更新，新建的資料庫直接包含。
- 站長要執行，我沒有執行也沒有部署：
  1. `bun run server:db:migrate`，先更新遠端資料庫的結構。
  2. `bun run server:deploy`，再部署伺服器。
  順序反過來，這段時間的教學事件會被資料庫擋下，不影響遊戲，只是教學統計會缺資料。
