# 戰鬥流程圖：改成專案自己的元件

這份規格來自一場完整的盤問，所有決策都已與使用者確認。票券在 `issues/` 底下，編號 01 到 06，依阻擋關係執行。新對話請先讀完這份，再領票券。

## 問題陳述

戰鬥流程圖是用外部工具 Archify 產生的獨立 HTML，放在 `public/` 底下隨網站部署，三個入口都用連結開新分頁。它有三個問題：

- 已過期。來源 `docs/戰鬥流程圖.source.json` 最後一次修改是 v0.10.1，之後隔了 49 個 commit 沒人更新，改規則時要叫外部技能重新產生整份 780 KB 的 HTML，所以沒人更新。
- 外觀與遊戲畫面不一致，圖的設計寬度固定橫向 1230×786，放進手機寬度會縮到看不清楚。
- 產物依賴外部工具，順序資訊在圖、`StepTracker`、引擎三處各寫一份。

## 解決方案

做成 App 內的 React 元件，圖用手寫 SVG 畫，用彈窗開啟。回合主幹的順序從 `StepTracker` 搬出來的共用表產生，與引擎對齊；分支手寫。

### 決策摘要

**互動與開啟方式**
- 圖是靜態的規則地圖，不做縮放、平移、追蹤路徑、說明卡、主題切換。
- 用 `Modal` 彈窗開啟，沿用更新日誌彈窗的做法。專案沒有路由套件，頁面切換只是 `useState`，戰鬥畫面在路由之上，所以不做獨立頁面。
- 原本三個連結入口（首頁兩處、戰鬥畫面上方一處）改成開彈窗的按鈕。
- 唯一的互動：從戰鬥畫面開啟時，把目前的步驟在主幹上標成「你在這裡」；從首頁開啟則不標。即時的步驟高亮不重做，戰鬥畫面上方的 `StepTracker` 已經有。

**版面與視覺**
- 【已改】原決策是直向單欄 420px，實作後不如舊圖好看，改成照舊圖的橫向分區版面：設計寬度 1230，回合、戰鬥、追擊結果、勝負、加賽各一條分區，標題與說明字級放大。手機上 SVG 固定最小寬度 980px，在彈窗內左右、上下拖曳捲動，標頭與關閉鍵不捲走。
- 中文在 SVG 裡不會自動換行，所以每個節點的文字在資料裡預先斷成標題一行、說明一行，並由測試檢查沒有超過字數上限。
- 配色直接讀 `styles.css` 的 CSS 變數，單一深色主題。回合階段用 `--good`、戰鬥步驟用 `--accent`、追擊成功用 `--good`、失敗與勝負用 `--bad`、條件分支用 `--combo`、備註用 `--muted`。

**內容**
- 移除舊圖的 3 張說明卡，條件只寫在邊的短標籤上，細節留給規則書與規則說明頁，不再多存第三份規則文字。
- 修正舊圖與規則書 `docs/連擊大師.md` 不一致的 4 處：
  - 加賽終點：一方先翻完怒氣區就落敗，雙方同時翻完才平手。舊圖畫成「全部同值就平手」。
  - 追擊判定：翻到裝備或增益一律失敗，戰鬥區沒有招式時一律失敗。舊圖只有在範圍內與不在範圍內。
  - 先手步驟：手牌沒有可打出的招式時展示手牌，不算收招。舊圖沒有這個分支。
  - 勝負檢查：規則書第十章寫的是每個不可分割的步驟結束後都檢查，包含重置階段的回合開始效果、抽牌階段抽走最後一張。舊圖只畫了傷害計算之後。新圖用一個旁註節點表達，不從每個節點各拉一條箭頭。
- 不畫效果觸發窗口，也不畫連線離線判負，它們不屬於回合流程。

**與引擎對齊**
- 把 `StepTracker` 內的步驟表搬到共用資料檔，`StepTracker` 與流程圖主幹都讀它。表以 `Phase` 為鍵，結構是分組加每個階段的一行提示。
- 主幹由共用表產生。分支手寫座標與文字。
- 順序只有一份來源，改了回合順序，`StepTracker` 與流程圖會一起動。

**清理與版本**
- 新圖補齊後，一次刪除舊的 Archify 產物，舊版本可從 git 歷史找回。
- 依 `docs/agents/versioning.md` 屬於新增 UI 模組，升到 v0.24.0，並在 `src/data/changelog.ts` 補一筆。目前版本是 v0.23.0。
- 舊圖的 README 說明提到可用 `archify` 技能重新產生，但目前環境裡並沒有這個技能，舊圖其實已無現成工具可更新。清理時全專案不應再留下 `archify` 的字樣。

### 事實備忘

- 引擎的 `Phase` 型別有 12 個值：設置、重置、先手、反擊、追擊、傷害、歸還、抽牌、爆發、增益、回合結束、結束。回合主幹用到除了設置與結束之外的 10 個。
- 規則書第五章是回合流程，第六章是戰鬥細則，第十章是勝負。詞彙以 `GLOSSARY.md` 為準。
- 手機斷點在 `styles.css` 是 900px 與 640px，彈窗 `.modal` 是 `max-width: 92vw`、`max-height: 86vh`、可捲動。
- 舊圖的結構可作內容參考：19 個節點、21 條邊，來源檔在清理前還讀得到。

## 範圍外

- 縮放、平移、追蹤路徑、說明卡、主題切換。
- 整張圖由程式資料產生（只有主幹由共用表產生）。
- 效果觸發窗口、連線離線判負。
- 戰鬥畫面上方 `StepTracker` 的外觀與行為變更。

## 測試策略

- 共用步驟表的順序涵蓋 `Phase` 除了設置與結束之外的所有值，且沒有重複。
- 流程圖分支引用的 `Phase` 都存在於 `Phase` 型別。
- 每個節點文字的行數與每行字數不超過上限。
- 給定 `Phase` 能算出要標示的主幹節點，沒有對應時回傳空。
- 視覺部分在瀏覽器實測：桌面寬度與手機寬度各開一次彈窗，確認字不被裁掉、可捲動。
