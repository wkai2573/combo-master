# 手機版面與拖曳使用

Status: resolved

## 問題陳述

手機上玩對戰很吃力：經驗區與手牌被疊住後，只能靠滑鼠懸停才看得到，觸控裝置沒有懸停；整頁要上下捲動，邊找牌邊看戰鬥區很累；能點選的卡一點就送出，手機誤觸成本高；所有出牌都只能點選，沒有拖曳。

## 解決方案

- 手機直立（寬 ≤ 640）用新的**手機版面**：整頁不捲動，對手縮成一條，經驗區與裝備增益區變成牌堆、點開從底部滑出面板，手牌固定在底部單列重疊。
- 觸控裝置上，能點選的卡第一下選取並浮出預覽，第二下才送出。
- 手牌可以拖到**放置區**直接使用，寬、窄兩版與滑鼠、觸控共用同一套手勢判斷。
- 橫向手機與平板沿用窄螢幕版，只補上不依賴懸停的修正。

## 實作決策

- 三種版面（寬螢幕版、窄螢幕版、手機版面）互斥，由一個純函式依視窗寬高與方向判斷。手機版面：寬 ≤ 640 且直立；寬螢幕版條件不變。
- 提示（Request）新增選填的放置區：經驗區、戰鬥區、裝備增益區三種。爆發階段是經驗區，先手與反擊步驟出招是戰鬥區，增益階段是裝備增益區；其餘提示不帶。提示本來就原樣傳給雙方視角，連線不需另外處理。
- 拖曳只在單選、帶放置區的提示、且畫面可操作時啟用；放開在放置區就送出，否則彈回。
- 手勢判斷純函式：輸入指標移動軌跡與放置區矩形，輸出點擊、捲動、拖曳與落點。觸控往上移動超過約 8px 立即開始拖曳，橫向移動當作捲動；滑鼠移動超過約 4px 才算拖曳。
- 觸控兩段點擊的狀態轉換為純函式：第一下選取並預覽，第二下送出；點別張改選；只有觸控裝置套用，桌機點一下不變。
- 手牌單列重疊延伸既有的手牌版面函式：卡約 64×90px，每張至少露出約 28px，放不下時橫向捲動。
- 底部面板是共用元件：手機版面的經驗堆、裝備增益堆、對手條與我方角色名都用它；內容遵守牌面可見性。
- 預覽卡浮在手牌上方，選取其他牌或送出後消失。
- 版本號：手機版面四張完成升次版號，拖曳三張完成升次版號，觸控修正完成升修訂號，都補更新日誌。

## 測試決策

- 好測試只看外部行為：給定提示或輸入，輸出的放置區、版面模式、手勢結果。
- 引擎的放置區在對局層測試，沿用既有的情境建立工具與對局測試的寫法。
- 版面判斷、手勢判斷、兩段點擊、手牌單列重疊都是純函式，沿用 tests 下版面函式測試的寫法。
- 畫面效果不做自動化 DOM 測試，用 Playwright 模擬約 390px 直立、橫向手機與平板手動實測。

## 不在範圍內

- 作弊面板的手機版。
- 戰鬥區卡牌的拖曳排序或其他拖曳用途。
- 效果要求選手牌、支付費用時的拖曳。
- 把點一下的舊操作拿掉。
- 自動化的 DOM／元件測試基礎設施。
