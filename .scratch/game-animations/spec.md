# 全場動畫：卡片飛行與統一演出

## 問題陳述

玩家在對戰時只看得到數字與標籤在變：抽牌、受到傷害、直擊、支付費用、回復這些動作，卡片從哪裡去了哪裡完全看不出來。牌組只是標頭的「生命 N」，棄牌與怒氣只是點了才開視窗的標籤，畫面上沒有牌組的實體位置，也就無從呈現「牌組上方幾張卡移入棄牌區」。現有的演出（追擊翻牌、攻守拼招算式、受傷震動）又各自為政，時長、配色、動作風格不一致。引擎只在約 15 個關鍵點錄影格，漏掉的步驟（例如支付費用）完全沒有演出，新加卡片效果時也容易漏掉。

## 解決方案

讓對戰中每一個會改變卡片位置或數值的動作都有演出，風格以 Yu-Gi-Oh! MASTER DUEL 為目標（不需完美）。

- 每位玩家的區塊多了實體牌堆：牌組（疊出厚度、顯示張數）、棄牌區（頂牌正面）、怒氣區（疊起來）。
- 抽牌、受傷、直擊、棄怒氣、回復、出招、歸還、追擊翻牌等卡片移動，都會看到卡片從原區域**逐張飛**到新區域。多張牌時自動加快，整段不超過約 1.5 秒。
- 飛行遵守可見性：自己抽牌飛正面、對手抽牌飛牌背、受傷進怒氣區一律飛牌背、進棄牌區途中翻成正面。
- 卡片效果發動時，該卡浮到畫面中央放大並壓暗桌面，搭配效果說明。
- 同一步驟裡連續的事（發動、付費、抽牌）各自一段，依序播放。
- 數值（生命、怒氣、經驗、總攻、總防、增益指示物）變動時閃一下並顯示差值。
- 每回合開頭與戰鬥主要階段有橫幅；開局有洗牌與起始手牌飛入；結束有勝負演出。
- 既有演出（追擊翻牌、攻守拼招、受傷）重做成統一風格。

## 實作決策

- **影格的自動保證（引擎）**：卡片移動、寫入紀錄，會在該步驟結束時自動錄一個影格。現有的手動標記保留，用來指定特殊演出類型（追擊翻牌、傷害算式、收招等）。「覆蓋」直接改旗標、沒走移動操作，要特別納入。壓測與測試不開動畫，不產生影格，維持零成本。
- **步驟分段**：同一個步驟裡連續的事（發動、付費、抽牌）各自錄一個影格，依序播放；每段約 0.4～0.8 秒，快速模式縮為 0.45 倍。
- **卡片飛行由前後影格比對推導**（見 ADR-0001）：不新增「移動事件」；以卡片穩定的 `uid` 與所在區域比對相鄰影格得出飛行清單。同一影格間移動兩次的卡只看得到起點與終點；這類動作（例如瞄準把牌放到牌組底再判定下一張）靠多錄一個影格補上。
- **影格新增卡片可見性欄位**：由主機依各自視角產生，聯機時不把對手看不到的牌面傳過去。聯機不新增訊息類型，影格照現在方式由主機錄製並傳給對手。
- **飛行清單（新模組）**：輸入兩個相鄰影格，輸出每張飛行卡的起訖區域、玩家、飛行時是否正面／途中翻面、多張時的順序與間隔。這是純函式，不碰 DOM。
- **牌堆實體位置（介面）**：每位玩家的區塊新增牌組、棄牌區、怒氣區的牌堆元件，也是飛行的起點與終點錨點。其餘版面不動。
- **飛行圖層（介面）**：一個蓋滿畫面、不擋操作的圖層，依各區域錨點的實際位置量出起點與終點，用瀏覽器內建的 Web Animations API 播放。不新增套件。
- **統一動畫語彙**：以 CSS 變數統一飛行、翻面、彈出的時長與緩動；統一色彩語意（攻擊橙紅、防禦藍、傷害紅、成功綠、發動金）；共用基本動作：飛行、翻面、中央放大（發動與追擊翻牌共用）、數字彈出、橫幅、震動；中央放大時桌面壓暗約 50%。保留現有深色加金色主題。
- **既有演出重做**：追擊判定改為牌從牌組堆飛到中央翻面放大，顯示成功／失敗，成功飛進戰鬥區、失敗飛進手牌。攻守拼招改為算式逐項出現、傷害數字重重落下，扣血一方的牌背逐張飛進怒氣區，第一張落下時震動並浮出傷害數字，沒有傷害的一方顯示綠色的 0。
- **播放控制**：沿用依序播放、播放中不能操作、跳過動畫、三檔速度；瀏覽器設定「減少動態」時預設速度為「關閉動畫」，玩家仍可手動改。
- **不做音效**。
- **發動演出**：所有卡片共用同一套通用演出（卡片浮到畫面中央放大、桌面壓暗、顯示效果說明），不做每張卡客製特效。
- **橫幅**：只放在每回合開頭與戰鬥主要階段，不是每個階段都放。
- **開局與結束**：開局為洗牌、先後攻決定、起始手牌逐張飛入，約 2 秒；結束為輸家變灰、贏家勝利特效，約 1.5 秒，之後才顯示現有的結果視窗。
- **分批交付**（每批可單獨使用）：
  1. 牌堆實體位置，加抽牌、受傷、直擊、棄怒氣、回復的逐張飛行，與影格自動保證、飛行清單、統一動畫語彙、可見性欄位。
  2. 出招、收招後歸還經驗區、追擊翻牌的飛行，與追擊與攻守拼招重做。
  3. 覆蓋經驗卡的翻面、裝備與增益的進出場，與發動演出、數值變化動畫。
  4. 瞄準、放回牌組頂或底、洗牌等較少見的動作，與橫幅、開局與結束演出、手牌滑過回饋。

## 測試決策

- **好測試的標準**：只測外部可觀察的行為。引擎端驗證「某個操作之後錄到哪些影格、各影格的桌面與可見性是否正確」；飛行清單驗證「給定兩個影格，輸出哪些卡從哪裡飛到哪裡」。不測內部呼叫順序，也不測 CSS 或 DOM 細節。
- **測試接縫（已與使用者確認）**：
  - 引擎端沿用現有的接縫：以情境建立遊戲、以選項文字回應提示、取出並檢視影格。
  - 新增一個接縫：相鄰兩個影格轉成卡片飛行清單，測試時用上述引擎接縫產生真實的相鄰影格，再丟給飛行清單。
  - 畫面層的實際動畫不寫單元測試，改用瀏覽器實跑驗證。
- **要涵蓋的行為**：每個會改變卡片位置的操作（抽牌、受傷、直擊、棄怒氣、回復、出招、歸還、追擊判定、支付費用）至少錄到一個影格；自己與對手視角下可見性欄位正確（對手手牌與怒氣為牌背、棄牌為正面）；多張牌移動的飛行順序與張數；沒開動畫時完全不錄影格。
- **先例**：既有的動畫影格測試（沒開動畫不錄影格；一次完整拼招依序錄下指定演出類型；對手怒氣內容隱藏但張數可見）。

## 不在範圍內

- 音效。
- 新增任何動畫套件。
- 每張卡片客製的特效。
- Master Duel 式完整遊戲墊的版面重做與 3D 效果。
- 播放期間可操作的非阻塞動畫。
- 聯機訊息類型的變更。
- 畫面層動畫的單元測試。
