# 單機練習啟發式決策機器人

## 問題陳述

目前「單機練習」模式下的電腦對手僅採用純隨機或極度簡單的硬編碼機率（50% 機率爆發或出增益、80% 隨機出招、20% 收招），且決策時完全未傳入桌面視角（無法得知血量、手牌、連擊值、攻守差距等資訊）。這導致電腦常常在先手步驟打出 0 攻卡導致被秒收招、無法組織連擊、在無法破防時胡亂出招浪費資源、在瀕死時爆發自殘，使得單機練習缺乏博弈樂趣與實戰參考價值。

## 解決方案

為單機練習引入一套嚴格遵守「牌面可見性（Face Visibility）」的啟發式決策機器人（Heuristic Bot）：
1. 僅根據電腦（玩家 B）自身的桌面視角（`GameView`）做決策，絕不透視玩家手牌、玩家暗牌或牌組頂。
2. 以「破防與連擊優先」為進攻核心，透過戰鬥區與手牌招式預估淨破防 ≥ 3 點之划算攻擊；未達破防門檻且對手威脅低（受傷 ≤ 3）時主動「收招保留」，對手威脅高（受傷 ≥ 4）時出防守招式減傷；並依據受傷威脅浮動提升防禦權重、依溢出破防給予攻擊加成。
3. 先手步驟排除 0 攻卡，並依手牌招式連擊值重心（`avgCombo`）優先打出手牌密集端之邊緣牌（手牌偏低端出 1～2，偏高端出 8～9），避免出中間牌導致後續手牌邊緣牌卡死。
4. 動態戰術切換：我方手牌張數比對方多 ≥ 2 張時切換為全力連擊，大膽維持較寬連擊開口以最大化手牌傾瀉；否則優先壓縮連擊範圍迫使對手收招。
5. 資源與血量管理：牌組剩餘 ≤ 6 張停止爆發，增益階段裝備優先於增益，觸發窗口按實質效益付費。

## 使用者故事

1. 身為單機練習的玩家，我想要電腦在先手步驟不主動出 0 攻擊力的招式，以便能正常展開攻防博弈，而非因我方第一手收招而讓先手平白吞下結算。
2. 身為單機練習的玩家，我想要電腦在先手步驟根據手牌分佈優先打出邊緣牌（手牌偏低出低端邊緣、手牌偏高出高端邊緣），以便電腦後續手牌的主力招式不會因初始範圍過窄而被鎖死。
3. 身為單機練習的玩家，我想要電腦在面臨對手高額傷害威脅時大幅提高防禦權重，以便電腦在危急時敏銳選出高防招式進行保命減傷。
4. 身為單機練習的玩家，我想要電腦在破防狀態下給予溢出攻擊力更高權重，以便電腦在確立優勢時全力傾瀉攻擊重創對手。
5. 身為單機練習的玩家，我想要電腦在對手手牌充足時優先打出能壓縮範圍或封鎖連擊值的卡，以便體驗雙方相互壓迫對手提早收招的博弈感。
6. 身為單機練習的玩家，我想要電腦在對手手牌稀少（我方手牌比對方多 2 張以上）時切換為全力傾瀉手牌並大膽維持連擊開口，以便感受對手資源耗盡後電腦最大化連擊輸出的節奏。
7. 身為單機練習的玩家，我想要電腦在無法打穿我方防禦（淨傷害 < 3 點）且我方威脅低時及時收招保留手牌，以便電腦不會盲目把手牌浪費進經驗區。
8. 身為單機練習的玩家，我想要電腦在我方攻擊極高（我方預期造成 ≥ 4 點傷害）且其無法破防時依然積極出高防卡防守，以便電腦不會因為無法破防而放棄防守被我方一波帶走。
9. 身為單機練習的玩家，我想要電腦在牌組張數小於等於 6 張時停止主動爆發，以便電腦不會在殘血階段自我抽牌自殘落敗。
10. 身為單機練習的玩家，我想要電腦在血量健康且手牌有多餘白板或難以使用的裝備時積極爆發換牌，以便電腦能穩定補充手牌資源。
11. 身為單機練習的玩家，我想要電腦在增益階段優先打出長效裝備而非暫時增益，以便電腦能建立長遠的攻防基石。
12. 身為單機練習的玩家，我想要電腦在觸發窗口中僅在受到實際傷害時才支付費用發動減傷效果，以便電腦能精確節省經驗與怒氣資源。
13. 身為單機練習的玩家，我想要電腦在使用遊俠瞄準時根據是否能追擊成功做出合理的頂牌或底牌選擇，以便練習遊俠角色時面對更逼真的操作。
14. 身為單機練習的玩家，我想要電腦嚴格遵守牌面可見性、不偷看我方隱藏手牌與暗牌，以便享受公平公正的對戰體驗。
15. 身為系統開發者，我想要機器人決策函式維持單一最高接縫且在無視角時平滑降級，以便所有既有壓測與測試 100% 保持相容通過。

## 實作決策

### 模組邊界與責任分工

- 新增專屬評估模組，集中負責啟發式評估演算法、連擊鏈模擬與出招評分。
- 既有機器人入口擴充接收玩家視角引數：
  ```ts
  botChoice(req: Request, rng: Rng, view?: GameView): string[]
  ```
  當 `view` 存在時委派給啟發式評估模組；當 `view` 未提供時（如舊單元測試或壓測腳本）平滑降級為原有的合法隨機回應。
- 單機對局會話（`LocalSession`）在推進機器人動作計時器時，將當前視角與提示請求一同傳入。

### 戰鬥反擊評估演算法

1. **划算攻擊判斷與動態攻防權重**：
   - 搜尋手牌中在當前範圍內的合法招式，評估結合當前戰鬥區後的攻守期望。
   - 計算淨傷害：`netDmg = projectedAtk - oppDef`。
   - 動態防禦權重：`threat = Math.max(0, oppView.atk - myView.def)`，`defWeight = 0.4 + Math.min(threat, 8) * 0.2`（最高達 2.0）。受傷威脅越重越重視防禦減傷。
   - 動態攻擊權重：基礎攻擊權重 1.0；若確認破防（`projectedNetDmg > 0`），溢出破防攻擊力享有 `breakthrough * 1.5` 線性激勵加成。
   - 若候選招式中最優之 `maxProjectedNetDmg >= 3`，判定為划算進攻，持續組織出招。
2. **收招保留與防守判定**：
   - 若無法達成划算進攻（`netDmg < 3`）：
     - 檢查當前受傷威脅：若直接收招將承受 `threatDmg = oppAtk - myDef`。
     - 若 `threatDmg >= 4`：生存優先，篩選能提高總防禦的招式（`def > 0`）出招防守減傷，並依動態防禦權重挑選最高減傷招式。
     - 若 `threatDmg <= 3`：執行「收招保留（Conserving Pass）」，選擇 `pass`。
3. **出招卡片評分權重**：
   - 計算資源差距：`handDelta = myHandCount - oppHandCount`。
   - 若 `handDelta >= 2`（對手手牌枯竭）：採用策略 A（連擊潛力優先），評分權重以「打出該卡後手牌剩餘可連招數」為主，大膽維持較寬連擊開口。
   - 若 `handDelta < 2`：採用策略 C（逼退對手），評分權重以「打出該卡後壓縮連擊範圍程度」與「封鎖連擊值」為主。
4. **先手步驟出招（手牌密集端之邊緣牌優先）**：
   - 排除攻擊力為 0 的招式（除非手牌招式全為 0 攻）。
   - 計算手牌招式的連擊值重心：
     ```ts
     const avgCombo = handMoves.reduce((sum, c) => sum + getCard(c.id!).combo, 0) / handMoves.length;
     ```
   - 若 `avgCombo < 5`（手牌偏低端）：目標為低邊緣，`edgeScore = (9 - card.combo) * 1.8`。
   - 若 `avgCombo >= 5`（手牌偏高端）：目標為高邊緣，`edgeScore = card.combo * 1.8`。
   - 帶有先手專用加成效果的招式（如 `[先]` 標籤）賦予額外權重加分（+15）。

### 非戰鬥階段決策

1. **爆發階段**：
   - 生命防線：自身牌組張數 ≤ 6 時，一律回傳空陣列（不爆發）。
   - 棄牌優先序：優先丟棄部位已滿或經驗需求過高（`expReq > myExp + 2`）的裝備，其次丟棄重複的白板招式。
2. **增益階段**：
   - 優先打出裝備（武器、防具、飾品），其次打出增益。同類別優先打出經驗需求較高者。
3. **觸發窗口與瞄準**：
   - 減傷效果：僅在 `damagePending > 0` 時才發動。
   - 遊俠瞄準（LV1）：若頂牌連擊值在範圍外（判定會成功）則選擇 `keep`；若會失敗且我方總攻擊亟需提升時選擇 `swap`，若需要補手牌則 `keep`。

## 測試決策

### 測試接縫（Single High Seam）

本功能採用**單一最高接縫**進行全面測試：
- 測試目標一律透過 `botChoice(req, rng, view)` 呼叫，傳入構造或實際遊戲衍生的 `GameView` 與 `Request`，斷言其回傳的選項鍵（`string[]`）。
- 不對內部微小輔助函式進行多層次 mock，完全驗證外部可觀測之決策行為。

### 測試覆蓋矩陣

1. **先手步驟**：手牌同時有 0 攻高防卡與有攻卡時，絕對不選 0 攻卡；有 `[先]` 標籤時優先選出。
2. **划算破防 vs 收招保留**：
   - 當預期淨攻擊能超出對方防禦 ≥ 3 點時，持續出招不收招。
   - 當無法破防且對手低攻（受傷 ≤ 3）時，回傳 `['pass']`。
   - 當無法破防但對手高攻（受傷 ≥ 4）且手牌有防禦招式時，優先打出高防招式而不收招。
3. **策略動態切換**：
   - 我方手牌比對方多 ≥ 2 張時，優先出能接續最多手牌的連擊卡。
   - 對手手牌充裕時，優先出壓縮範圍之招式。
4. **爆發血量安全線**：
   - 牌組 ≤ 6 張時不爆發（回傳 `[]`）。
   - 牌組健康時爆發，並優先選擇暫時無法裝備的卡片。
5. **增益與減傷**：
   - 同時有裝備與增益可打時優先選裝備。
   - 未受傷時不發動復仇之嚎等減傷。
6. **相容性測試**：
   - 未傳入 `view` 時調用 `botChoice(req, rng)` 維持原本合法隨機行為，全站 908+ 測試保持 100% 通過。
7. **邊緣牌優先與動態權重精進（0.47.1）**：
   - 手牌重心偏低（`avgCombo < 5`）先手出低端邊緣（如 1、2）；手牌重心偏高（`avgCombo >= 5`）先手出高端邊緣（如 8、9）。
   - 受傷威脅高時，動態防禦權重提升，優先挑選最高減傷之防禦招式。
   - 破防狀態下，溢出攻擊享有 1.5 倍加成，激勵全力灌傷。
   - 對手手牌少時維持連擊開口，最大化手牌出招鏈長度。

## 不在範圍內

- 多層級難度選單 UI（大廳維持簡潔，直接全面升級單機練習對手）。
- 作弊透視對手手牌或牌組頂的全知 AI。
- 多線程 Web Worker 蒙地卡羅樹搜尋（MCTS）。
- 聯機對戰時的代打機器人。
