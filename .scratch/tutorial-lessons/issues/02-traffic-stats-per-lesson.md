# 02：流量統計分課

**要建置什麼：** 流量統計的教學事件記下是哪一課。事件資料表新增一個可空的課程欄位，只有教學事件會填；對戰類型仍是單一的「教學」，不另增類型。教學場次依課程送出開始與完成事件，「重來本課」視為重新開始，記一次新的開始。伺服器的事件驗證只允許教學事件帶有效的課程編號，其他事件帶課程欄位要拒絕，不存在的課程編號也要拒絕。既有沒有課程欄位的教學事件，報表一律歸為第 1 課。站長的流量統計報表把教學那一列展開為每課一列，各列顯示開始數、完成數、完成率；總覽、每日、依版本仍不計教學。需要一份資料庫遷移，排在票券 `.scratch/tutorial/issues/06` 的遷移之後；遷移與伺服器部署由站長執行，票券的答案裡要寫明兩個遷移一起部署時的順序不能顛倒。

**Blocked by（被誰阻擋）：** 01

**Status：** resolved

- [ ] 事件驗證測試：接受教學事件帶有效課程編號；拒絕非教學事件帶課程欄位；拒絕不存在的課程編號；仍拒絕不認得的對戰類型
- [ ] 遷移測試：事件資料表有課程欄位，既有教學事件的課程欄位為空；遷移排在上一個教學遷移之後
- [ ] 教學場次測試：進入某一課送出帶該課編號的開始事件，走到結束畫面送出帶該課編號的完成事件；重來本課送出一次新的開始事件；中途離開不送完成事件；仍不送出戰績
- [ ] 報表測試：舊的空課程事件歸第 1 課；教學那一列展開成每課一列，顯示開始數、完成數、完成率；總覽、每日、依版本仍不計教學
- [ ] 在答案中寫明站長要執行的資料庫遷移與伺服器部署順序，以及部署前送出的帶課程欄位事件會被舊伺服器拒絕這個已知情形
- [ ] 升版並補更新日誌（若無玩家可見變化則依版本規範處理）；`bun run test`、`bun run build` 通過

## Answer

已於 v0.50.1 生效（沒有玩家可見的變化，不補更新日誌）。

**站長要做的事（遷移與伺服器部署由站長執行）：**

1. 先確認 `.scratch/tutorial/issues/06` 的 `0001-events-allow-tutorial.sql` 是否已在遠端執行過（它重建 events 資料表，可重複執行）。
2. 執行 `bun run server:db:migrate`：依序跑 `0001`、再跑 `0002-events-add-lesson.sql`。**兩個遷移一起部署時順序不能顛倒**：`0001` 重建 events 時只搬它認得的欄位，若 `0002` 先跑，課程欄位會被丟掉（`tests/eventsMigration.test.ts` 有這個情境）。
   - `0001` 已經跑過的話，這個指令的第一段只是重跑一次（安全），第二段才是新的。
   - `0002` 不能重複執行：欄位已存在時會報 `duplicate column name`，資料不受影響，看到這個錯誤代表已經遷移過了。
3. 再 `bun run server:deploy` 部署伺服器。
4. 最後才把遊戲推到 `main`。

**已知情形：**
- 新版遊戲在伺服器部署之前送出的教學事件帶有 `lesson`，舊伺服器的驗證不認得這個欄位、直接忽略，事件照存但課程是空的，報表會把它們當成第 1 課。目前只有第 1 課所以沒有影響，但第 2 課以後上線前一定要先部署伺服器。
- 反過來，新伺服器部署在還沒執行 `0002` 的資料庫上，寫入教學事件會因為沒有 `lesson` 欄位而失敗（造訪與一般對局的事件也會一起失敗，因為 INSERT 語句都包含這個欄位），所以務必先遷移、再部署伺服器。這段時間送不進去的統計不會補，不影響遊戲。

**其他：**

- 伺服器：`server/src/lessons.ts` 的 `KNOWN_LESSONS` 是伺服器認得的課程編號，`tests/events.test.ts` 會對照遊戲的 `LESSONS`，新增課程時兩邊要一起改。
- 驗證：課程欄位只能出現在教學的開始與完成事件，其他事件（含造訪、心跳）帶了就 400；不存在的課程編號 400；教學事件沒帶課程欄位（舊版遊戲）照收，課程存成 NULL。
- 教學場次：開始與完成都帶 `lesson`；完成是走到結束畫面（不再依賴對局分出勝負，因為第 2 課起不打完整場）；「重來本課」記一次新的開始。
- 報表（`bun run stats`）：教學不再出現在「依對戰類型」，改成獨立的「教學（每課）」一列一課，顯示開始數、完成數、完成率（完成場次占開始場次）；空課程的舊事件歸第 1 課；總覽、每日、依版本仍不計教學。`bun run stats` 讀 `lesson` 欄位，所以要在 `0002` 遷移之後才能用。
