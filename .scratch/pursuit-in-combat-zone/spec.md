# 追擊卡納入戰鬥區

## 問題陳述

現在引擎把追擊成功的卡放在獨立的追擊區，規則詮釋明寫「追擊卡不算在戰鬥區裡」，盾擊的詮釋也寫「不含追擊卡」。實際想要的規則是：追擊成功的卡另外疊成一疊，但算在戰鬥區裡，所有卡效果提到戰鬥區的地方都要包含它。

## 解決方案

詞彙見 `GLOSSARY.md`，新增三個詞並釐清彼此關係：

- **招式卡疊**：戰鬥階段打出的招式所疊成的那一疊，也就是現在程式裡的 `combat` 區。
- **追擊卡疊**：追擊成功的卡所疊成的那一疊，也就是現在的 `pursuit` 區，與招式卡疊分開疊放。
- **戰鬥區**：招式卡疊加追擊卡疊。

### 決策摘要

- 卡效果寫「戰鬥區」的地方，一律包含追擊卡疊。受影響的卡：電弧數對方戰鬥區招式數量、盾擊提升攻擊力、凡骨的意志數白板卡、冰與雷之曲判斷特徵。卡表上這幾張的文字不用改。
- 下列規則本身仍然只看招式卡疊，追擊卡不影響：範圍內判定、重複連擊值、[頂]、歸還順序（招式卡疊由底到頂，最後才是追擊卡疊）。
- 盾擊：追擊成功的招式卡也會被提升，追擊卡一落地就適用，結算時算進去。
- 二刀連擊：條件改成只看招式卡疊，文字改為 `[頂]：若我方招式卡疊僅有此卡，追擊+1。`。條件不受追擊卡影響，所以追擊中途不會變化。這張卡的新文字要更新到卡表網頁，再同步 `src/data/cardTable.json`，由 Claude Code 處理。
- 程式內的區名：`combat` 改名成 `moves`（招式卡疊），另外提供「戰鬥區」的取法，回傳招式卡疊加追擊卡疊。畫面與紀錄中原本顯示「戰鬥區」的地方，依實際指的是哪一疊改用準確的詞。
- `docs/規則詮釋.md` 第 6、19 條與盾擊的說明同步修改，把「追擊卡不算在戰鬥區裡」改成新規則。

## 範圍外

- 外框顏色，見 `.scratch/card-class-border/spec.md`。
- 追擊判定本身的流程、[追] 效果與追擊值的計算。
- 新增依新規則才有意義的新卡。

## 測試策略

- 區名改名後，既有測試全部照舊通過，行為不變。
- 新增測試：每張受影響的卡，追擊成功後它的戰鬥區計數、特徵或提升確實包含追擊卡。
- 新增測試：範圍內判定、重複連擊值、[頂]、歸還順序不受追擊卡影響。
- 二刀連擊：招式卡疊只有此卡時追擊+1；追擊成功後額外翻牌仍照常，不被追擊卡取消。
