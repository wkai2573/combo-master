# 階段表：階段順序只寫一次

## 問題陳述

回合內的階段順序在 `src/engine/game.ts` 寫了三遍：`run()` 的條件鏈（每個階段前一長串起點比對）、`runSinglePhase` 的 switch，以及戰鬥階段內部。詞彙表「階段執行接縫」宣稱可以指定任何起始階段，實際上指定 `追擊`、`傷害`、`歸還` 都會悄悄從 `先手` 重跑，因為 `combatPhase` 是一整塊。測試實際用到的起點只有 `重置`、`先手`、`爆發`。新增一個階段要同時改三處條件。

## 解決方案

詞彙見 `GLOSSARY.md` 的「階段執行接縫」。

新增有序的階段表，完整對局、從階段 X 開始、只跑階段 X 三種驅動方式都讀它。起始階段的型別 `StartPhase` 縮成真正能當起點的 `重置`、`先手`、`抽牌`、`爆發`、`增益`；`Phase` 仍是顯示用的完整階段名稱。

### 決策摘要

- 階段表每一項是「起點名稱」加「執行函式」；完整對局從起點的索引開始往後跑，單階段只跑那一項。
- 戰鬥階段整塊是一項（起點名稱 `先手`），內部的反擊、追擊、傷害、歸還不拆。
- 完整對局裡戰鬥階段開頭的橫幅影格只在完整對局出現，單階段不錄，與現在一致。
- 起始階段只適用於第 1 回合；之後的回合一律從頭。
- 詞彙表的「階段執行接縫」改寫成與實作一致。

## 範圍外

- 把戰鬥階段拆成可獨立進入的步驟。
- 階段的顯示名稱與介面。

## 測試策略

- 既有的 `cards2`、`window`、`awakening` 測試不改斷言。
- 新增階段表的測試：每個起點都能進入並跑完該階段；從某個起點開始的完整對局，不會執行它之前的階段；單階段只跑那一項。
