# 單機練習採用遵守牌面可見性的啟發式決策機器人

單機練習的電腦（玩家 B）採用結合「連擊潛力評估」與「戰鬥攻守精算」的啟發式決策機器人（Heuristic Bot）。決策嚴格遵守牌面可見性（Face Visibility），僅依據玩家 B 自身的桌面視角（GameView）進行判斷，絕不透視玩家手牌、牌組頂與怒氣區。

## 考慮過的選項

- **純隨機/簡單機率（原本的實作）**：完全不看桌面狀態，出招與收招皆為隨機或固定比例，無法提供具有博弈感的單機練習體驗。
- **全知引擎存取（Cheating / Oracle）**：讓電腦直接讀取 Game 的完整 GameState，預知玩家手牌與即將抽到的牌。雖容易實作極限最優解，但違反牌面可見性原則，且會給玩家帶來被看穿的不公平挫折感。
- **蒙地卡羅樹搜尋（MCTS / 盤面模擬）**：對手手牌未知需進行大量判定化虛擬抽樣，在瀏覽器單線程執行容易造成介面卡頓且調校黑盒化。
- **遵守牌面可見性的啟發式決策（採用）**：
  1. 破防與連擊優先：先手防 0 攻秒收招；對手手牌較少（我方多 ≥ 2 張）時最大化連擊潛力，否則優先壓迫對手收招；
  2. 划算攻擊與生存防線：以戰鬥區＋手牌易連擊的招式預估，淨破防達 3 點以上才發動全力進攻；若無法破防且對手威脅低（受傷 ≤ 3）時主動收招保留；若對手高攻（受傷 ≥ 4）則以防守減傷優先；
  3. 資源管理：牌組剩餘 ≤ 6 張時停止爆發，增益階段裝備優先於增益；
  4. 向下相容：以選用參數 `view?: GameView` 接入，未傳入視角時降級為合法隨機回應，完全相容舊有壓測與測試。

## 後果

- 單機練習體驗大幅提升，電腦會主動組織連擊、逼退對手並管理血量與資源。
- 運算耗時 < 1ms，保持原有的 900ms 擬真出招節奏，完全不阻塞主執行緒。
- 既有測試與壓測腳本（`scripts/simulate.ts`）不受影響。
