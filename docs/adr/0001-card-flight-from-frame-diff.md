# 卡片飛行由前後影格比對推導，引擎不發移動事件

為了讓抽牌、受傷、直擊等卡片移動有飛行動畫，介面比對相鄰兩個影格中每張卡片的 `uid` 與所在區域，自己算出飛行路徑；引擎不新增「卡片移動事件」，`move()` 的呼叫點也不用改。

## 考慮過的選項

- **引擎在 `move()` 發出移動事件**：能精確描述同一步驟內移動兩次的卡片，但要改動所有移動呼叫點、擴充聯機協定與測試，傳輸量也較大。
- **前後影格比對（採用）**：影格本來就有每張卡的穩定 `uid`（連對手看不到的牌也有），不需要新的訊息類型。代價是同一影格間移動兩次的卡只看得到起點與終點，這類動作（例如瞄準把牌從牌組頂放到牌組底）靠多錄一個影格補上。

## 後果

- 引擎要保證每個會改變卡片位置的步驟結束時都錄影格，否則兩個影格之間會有多段移動被合併。
- 影格要帶卡片可見性，由主機依各自視角產生，避免把對手看不到的牌面傳過去。
