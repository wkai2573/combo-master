# 只有網站建置要用的圖片進 git，完整資產用 Releases 發布

無框原圖、成品卡面與各種製作過程的圖片反覆更新，讓打包後的 repo 膨脹到約 2 GB。現在圖片資產集中在 `assets/`，只有網站建置要用的 `assets/portraits/` 與 `assets/frames/` 進 git，`assets/originals/` 與 `assets/finished/` 只留本機。`public/` 的靜態檔同樣進 git。`.gitignore` 預設忽略圖片格式，再逐一放行上述位置。

整個 `assets/` 用指令打包成快照，發布到這個公開 repo 的 GitHub Releases，作為本機檔案的遠端保存與下載來源。指令用法見 README 的「資產」章節。

既有歷史中的其他圖片已用改寫歷史的方式清除；放行位置裡的舊版本也一併清除，只保留清理當下的版本。

## 考慮過的選項

- **只停止追蹤，不改寫歷史**：commit 不會改變，但 repo 大小不會下降。
- **所有圖片都移出 git，部署時下載資產包**：每次改圖都要先發布資產包才能部署，git 還要記錄採用哪一版。上傳漏掉或版本對不上時，部署會失敗或拿到舊圖。網站要用的圖片只有十幾 MB，不值得多這層相依。
- **只忽略當時存在的幾個圖片目錄**：擋不住之後新增的中間產物目錄。
- **打 tag 後由 GitHub Actions 打包**：Actions 只拿得到 git 裡的內容，打包不到只留本機的圖片。
- **用 git hook 在推送 tag 時打包**：每台電腦要另外安裝，推送還會卡到上傳完成。
- **私有 repo 或雲端儲存**：原圖可以公開，不需要另外管理權限與帳號。

## 後果

- 原圖與成品圖要執行發布指令才有遠端副本，沒發布的修改只存在製作者的電腦。
- 資產包是公開的，不能公開的檔案不可放進 `assets/`。
- 新增網站要用的圖片位置時，要同步在 `.gitignore` 放行。沒放行的圖不會進 git，建置也不會報錯，線上站只會缺圖。
- 網站插畫與卡框每次更新仍會讓 repo 變大。
- 清理前的 commit SHA 大多已經失效，先前記下的 SHA 在目前的歷史裡找不到。切回舊 commit 時畫面會缺圖。
