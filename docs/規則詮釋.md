# 規則詮釋與預設設定

`連擊大師.md` 與 `連擊大師.xlsx` 有些地方沒寫清楚。下面是實作時採用的解讀，**請你確認或指正**。要改的話，大多只要改 `src/engine/combat.ts`、`scripts.ts` 的對應處。

## 一、已由你決定的規則

- 勝負：牌組歸零者落敗。
- 同時歸零：手牌多者勝；手牌相同，雙方洗勻自己的怒氣區並逐張翻開，連擊值大者勝，同值就繼續翻；一方先翻完則落敗，雙方同時翻完則平手。
- 連線：PeerJS 點對點，不做防作弊。

## 二、基本規則的解讀

1. **牌組張數＝生命值。**起始 5 張手牌取自主牌組，所以開局生命值是 45（法師起始 7 張，開局 43）。
2. **牌組只要變成 0 張就落敗**，即使那是剛抽走的最後一張。勝負在每個「不可分割的步驟」結束後檢查（抽牌階段、傷害計算、追擊、爆發、增益、回合結束），所以雙方同時歸零才會走加賽判定。
3. **經驗區的牌預設表側**進入。「蓋X」是把 X 張表側經驗轉為裏側才發動後面的效果；只能從**最前面**開始蓋、不能選擇，不分是不是正在發動效果的那張卡（經驗區裡的 [經] 卡最前面就是自己時，會蓋到自己）。「打開」是翻回表側。卡片轉為裏側後就無效：裏側的牌不能發動 [經] 效果。**裏側的牌只對擁有者顯示牌面**：自己看得到牌面（畫面上加半透明黑色遮罩，可以查看說明與選擇），對手只看到牌背（`?`）；翻回表側（打開）或進入公開區（例如被捨棄進棄牌區）時雙方才都看得到，遊戲紀錄也不會寫出對手裏側卡的卡名。見 ADR 0003。
4. **「重置階段」**目前沒有任何卡使用橫置狀態，所以階段保留但不做事。
5. **先手步驟沒有可出的招式**：展示手牌，不視為收招；之後輪到先攻方時，若手牌出現可出的招式（後續範圍改變時）仍可出招。
6. **範圍內**：雙方戰鬥區最後一張招式的連擊值（含）之間。只要任一方戰鬥區沒有牌，就視為全部在範圍內（追擊判定也一樣，所以此時追擊必定失敗）。
   **重複連擊值**（已與你確認）：每個人的戰鬥區只能出現一次重複。第一次重複（同一個連擊值打出第 2 張）可以；之後戰鬥區裡已經有的連擊值，一張都不能再打出，只能打新的連擊值。例：我依序出 8、5、5、3、3、2，第 2 張 5 是第一次重複，可以；之後 3 已在戰鬥區，第 2 張 3 就不能打，只能打還沒出現過的連擊值。再例：我 4、對方 5、我再 4、對方再 5，我還能出 5，因為 5 對我是新的連擊值；這時對方範圍是 5～5，但他已經重複過，5 又已在他的戰鬥區，所以不能出牌。追擊卡不算在戰鬥區裡。
7. **「後攻在反擊步驟第 1 個動作就收招，直接進入傷害步驟」**解讀為連追擊階段一起跳過。手中沒有可出招式而自動收招，也算收招。
8. **追擊判定**：翻開非招式卡（裝備、增益）一律追擊判定失敗，加入手中。招式卡則檢驗連擊值是否不在範圍內，不在範圍內才判定成功，成為追擊卡。
9. **傷害**＝對手總攻擊 − 我方總防禦，≤ 0 不處理；雙方各自計算、同時生效。
10. **回復 X**：把怒氣區上方 X 張放回牌組頂（生命值增加）。
11. **歸還步驟**：戰鬥區由最底到最頂，最後才是追擊卡，依序加到經驗區最後方。
12. **費用**：[蓋X]、[怒X] 的效果都視為「可選」，付得起才會詢問；沒有費用的 [發] 效果則自動發動。
13. **先攻方優先**：雙方都可選擇的動作（爆發、增益、窗口詢問）都是先攻方先、後攻方後，所以沒有「同時隱藏出牌」。
14. **觸發窗口**：同一時機有多個效果可發動時，不再照固定順序一個個問，而是開一個窗口：玩家從清單選要發哪個、先發哪個，也可以選「結束」不再發動剩下的。每個效果在窗口內最多發動一次；每發完一個就重新檢查剩下的（例如費用付不起了就從清單消失）；清單上只剩一個可選效果時，維持原本的「發動／不發動」確認。強制效果在清單上標「強制」，只能排序、不能跳過，清單上還有強制效果時沒有「結束」。先攻方先處理完自己的窗口，再換後攻方。目前用在五個時機：回合開始（家族相片可選，凡骨的意志與中毒強制）、傷害計算後（每張復仇之嚎各算一個效果，可選）、收招時（冰與雷之曲，可選）、一次蓋到多張有蓋反應的卡（低價買進、高價賣出，強制，由卡的擁有者決定先後）、爆發後（招財貓、商人的調整順序、覺醒商人的把表側經驗加入手牌，三個都可選）。窗口中發動的效果再造成別的效果時，會另外開新的窗口依序處理。
15. **覺醒時的效果**：覺醒是狀態，經驗區張數達到角色的覺醒經驗就是覺醒。每次由未覺醒變成覺醒才算「進入覺醒」，退出覺醒（例如經驗被拿回手牌）後再次達標會再算一次。偵測在可能讓經驗區張數改變的步驟之後做：爆發、歸還、增益階段開始時的增益到期。開局時已經覺醒的狀態不算進入覺醒。目前只有遊俠有覺醒時的效果：當我方覺醒時，可以抽 2（選發）。如果同一步驟已經有要開的窗口（例如爆發），覺醒時的效果就在同一個窗口。

## 三、卡片效果的解讀

> 遊戲目前使用 36 張花色招式，加上各職業的新卡與裝備（見下方「目前開放的職業新卡」）。新卡一次開放一小批，先調順再加。
> **加一張新卡的流程：**
> 1. 在卡表網頁新增這張卡；有效果文字的先由 Claude 擬描述、你確認。從卡表更新卡片時，一律先依 `docs/卡片撰寫規範.md` 檢查文字；不符合就直接改寫，並且把卡表上的文字同步更新（遊戲裡有測試掃描全部卡文，不符合會失敗）。
> 2. 確認後在 `src/engine/scripts.ts` 實作效果，並把卡名加進 `src/data/enabledCards.ts` 的 `ENABLED_EFFECT_CARDS`（它就會出現在組牌卡池、能通過牌組驗證）。
> 3. 想放進預設牌組，到 `src/data/presetDecks.ts` 的 `PRESET_EXTRAS` 填上「角色 → 卡名 → 張數」。
> 4. 跑 `npm test` 與 `npm run sim`（機器人壓測）確認沒問題。

**裝備／增益通則**：經驗區張數 ≥ 經驗需求才能在增益階段打出（增益階段在歸還步驟之後，所以包含剛歸還的牌）；同部位已有裝備時不能再打出；同名增益只能 1 張；每回合 1 次。

### 卡表網頁與新卡流程

- 卡名、類型（招式／裝備／增益，裝備含部位）、職業、特徵，以及角色的名稱與職業，也可以在卡表網頁改。改名只改畫面上的名稱，遊戲內部 id（程式、啟用清單、牌組、測試都用它）固定為改名前的名字；同步時腳本會印出「卡名已改」「類型已改」「特徵已改」「角色職業已改」等提醒。注意：白板卡（花色招式）的判斷是「沒有特徵、沒有效果文字」，替白板卡加上特徵後它就不再自動啟用；角色改職業會改變他能用的專用卡。
- 數值（攻、守、連擊、經驗需求、持續回合、角色生命值與覺醒經驗）以卡表網頁為準，用 `npm run table -- <資料夾>` 同步成 `src/data/cardTable.json`。
- 同步完成後的收尾（Claude 做）：① 把資料庫 `meta/sync` 的遊戲版本、備註與同步時間更新；② 把卡、角色、關鍵字文件中 `base` 與現值不同的欄位重設成現值，卡表網頁的黃框與「尚未同步的改動」才會清掉，但絕不改 `base.name`（同步腳本用它當內部 id，改了遊戲會把這張卡當成新卡）；③ 重新讀回資料庫確認 `base` 全部與現值一致，再重跑一次同步，確認 `cardTable.json` 沒有變動。
- 新增的卡：沒有效果文字的純數值招式（無特徵、無文字）會自動啟用；有效果文字的卡先標「待確認用語」，由 Claude 擬定描述、你確認後才實作並加進 `ENABLED_EFFECT_CARDS`。
- 所有新描述依 `docs/卡片撰寫規範.md` 的句型撰寫：每行依序為 (回合X次)、[標籤_費用]：、時機、條件、效果，同類用語一致（總攻擊／總防禦、追擊判定、取代／追加）。

### 關鍵字

- 關鍵字在卡表網頁的「關鍵字」分頁維護（名稱、分類、說明），同步成 `src/data/cardTable.json` 的 `keywords`。分類有標籤（先追發頂經覺）、費用（蓋X、怒X）、動作（抽X、回復X、追擊+X）、名詞、角色技能（瞄準）、書寫規範。
- 卡上與角色文字只引用名稱：`[發_蓋3]` 會拆成「發」「蓋X」；`【瞄準】` 直接引用；兩個字以上的名稱（例如「回復」「總防禦」）直接出現在文字中也算。書寫規範只是寫卡的規定，不在遊戲裡顯示。
- 帶可變部分的名稱用樣式比對：「OO升級X」（OO＝2 字技能名，例如「瞄準升級1」）、「(回合X次)」。「Ex卡-卡名」只是命名規則的說明。
- 角色技能有等級：所有角色技能基礎為 LV1；「OO升級X」使 LV+X（本回合有效）。瞄準 LV1：看牌組頂 1 張並選擇放到牌組頂或底；LV2：抽 1，然後選手中 1 張卡放到牌組頂或底。
- 「獲得【瞄準】」是多一個瞄準，每個瞄準每回合 1 次：遊俠 1 個、覺醒再 +1、瞄準器再 +1，所以最多每回合 3 次。
- 測試會檢查：開放中的卡與角色文字用到的 `[標籤]`、`【名稱】` 都必須在關鍵字區塊有定義（Ex 卡的卡名括號除外）。

Ex 卡（臨時額外卡，不在牌組裡，也不能組進牌組）：**Ex卡-中毒**——[經] 我方後攻的回合開始時，直擊我方 3；離開經驗區時移除遊戲。

預設牌組（`PRESET_EXTRAS`）：勇者、後人：戒備打擊、復仇之嚎、盾擊各 2；刺客、先人：伏擊、二刀連擊、順手牽羊各 2；商人：低價買進、高價賣出、交涉、即時停損各 2；法師：力量爆破、電弧、火球、冰霜護甲各 2；遊俠：魅影射擊、地雷陷阱、二連矢、狙擊印記各 2。

### 角色

| 角色 | 解讀 |
|---|---|
| 勇者 | 「總和攻擊」指加成前的總攻擊（含追擊卡）；≥ 15（覺醒 10）時 +3。 |
| 刺客 | 此回合每次追擊判定成功 +1（覺醒 +2）；多次成功累加，這項加成合計最多 +5（覺醒後上限不變）。 |
| 商人 | 爆發後（有放 1 張手牌進經驗區並抽牌）：可以調整我方表側經驗的順序（蓋X 從最前面開始蓋，裏側的卡位置不動）；覺醒後再追加：可以把 1 張表側經驗加入手牌。取代了舊版的「抽 1 看 2 選 1」與「手牌 > 3 張 +3」。 |
| 法師 | 起始手牌 7 張。覺醒：抽牌階段額外抽 1（牌組，不再是怒氣區）。 |
| 先人 | 先攻回合攻擊 +（出招張數 − 1）；覺醒：先攻回合追擊 +1（追擊判定多翻 1 張，同幸運兔腳的「額外翻牌」，不是追擊卡攻擊 +1）。 |

| 遊俠（弓箭手） | **我設計的**（xlsx 該列是空的，資料放在 `src/data/characterFill.ts`）。獲得【瞄準】（覺醒再獲得 1 個；每次進入覺醒時可以選擇抽 2，見下）：每個瞄準每回合 1 次，LV1 看牌組頂 1 張並選擇放到牌組頂或底（提示會告訴你以目前範圍這張會判定成功或失敗），LV2（狙擊印記）抽 1 後選手牌放到牌組頂或底。選「就用這張」不消耗次數；牌組只剩 1 張時 LV1 不詢問。生命值 50、經驗需求 8。 |

## 四、預設牌組

**預設牌組**（`src/data/presetDecks.ts`）：底牌是花色招式（每個連擊值 1~9 各 4 種花色），再放進各職業的新卡（`PRESET_EXTRAS`，見上）。花色招式的取捨依每個角色的打分函式：

| 角色 | 風格 |
|---|---|
| 勇者 | 高攻擊，容易達成「總攻擊 15 以上」 |
| 後人 | 高防禦，搭配後攻 +1 防禦 |
| 刺客 | 集中在中段連擊（4~6），範圍較窄、追擊較容易成功 |
| 先人 | 集中在兩端連擊（1、2、8、9），範圍寬、容易連續出招 |
| 商人 | 攻守均衡 |
| 法師 | 集中在高連擊值（7~9） |
| 遊俠 | 集中在中高連擊（5~7），搭配瞄準 |

規則：每個連擊值先拿 3 種各 1 張（確保都接得上），其餘依分數補滿，同名最多 3 張、同連擊值最多 7 張。用 `npm run presets` 可以看各牌組的連擊值分佈與平均攻守。這是**初版**，各角色的牌組差異還不大，等實際玩過再調。

### 作弊模式

用來快速建立想測的場面，不是正式規則：單機練習與朋友連線的對戰畫面頂端都有「作弊模式」開關，開啟後畫面頂端標示「作弊模式開啟中」，並出現「作弊面板」。開關只存在那一局，離開或開新局都會回到關閉。

- **加入手牌**：可以從全卡池挑卡加入我方或對方的手牌，含尚未開放的卡，不含 Ex 卡；面板可以搜尋卡名、依職業篩選。
- **移除手牌**：把我方或對方的手牌移出遊戲，不會進棄牌區。
- **牌堆順序**：看得到雙方的牌組、怒氣區、棄牌區、經驗區，包含對方的牌組與雙方的裏側卡；拖曳或按 ◀ ▶ 調整順序。經驗區的順序會影響蓋X 先蓋哪幾張。戰鬥區、裝備、增益不能動。
- **時機**：任何時候都能操作，只有動畫播放期間鎖住（可按「跳過動畫」）。目前提示的選項正在引用的卡不能移除，也不能挪動位置，面板會說明原因；手牌在提示出現之後才加入，要等下一個提示才選得到。
- **紀錄與動畫**：每個作弊操作都寫進遊戲紀錄（開頭是【作弊】）；作弊的變化不演動畫。操作後會重新檢查勝負。
- **連線**：房主與訪客各自開關自己的作弊模式，都能操作雙方牌區。任一方開啟時，對方畫面頂端會顯示「對手開啟了作弊模式」，關閉後消失；開關與每個作弊操作都寫進雙方可見的紀錄，並寫明是誰做的。作弊檢視只給開啟的那一方，另一方的視角不變。訪客的操作傳給房主執行，被拒絕時訪客會看到原因，例如畫面已過期或提示正引用該卡，畫面同時更新為最新狀態。動畫播放期間各自的作弊面板鎖定。
- 沒有防作弊機制的立場不變：作弊不需要對方同意，只靠橫幅與紀錄讓雙方知情。

## 五、已知限制

- 斷線只做「離線 30 秒判負」，沒有重連回原局。
- PeerJS 使用公開 broker，雙方網路較嚴格時可能連不上（沒有 TURN）。
- 單機練習的對手是「偏積極的隨機機器人」，不是 AI。
- 卡面沒有插圖，只有文字卡框。
- 平衡尚未調整。隨機機器人互打的勝率只能當冒煙測試，不能反映真人對戰強弱。
